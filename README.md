# Green-Grid_SVVV Insights

Build a Complete Full-Stack Website: Green-Grid_SVVV

Act as a senior full-stack developer, UI/UX designer, and sustainability technology expert. Build a modern, responsive, functional website called Green-Grid_SVVV — Smart Campus Sustainability Platform for the KAUSHAL 8.0 hackathon, problem statement PS-04: Sustainable Tech Without Limits.

1. Project Objective

Create a software-based platform that helps colleges monitor, understand, and reduce resource consumption. The website should track electricity, water, waste, and paper usage, calculate sustainability metrics, identify wastage, and recommend practical actions.

The website must demonstrate a working MVP suitable for an 8-hour hackathon. Focus on working features rather than unnecessary complexity.

2. Technology Stack

Frontend: React, TypeScript, Tailwind CSS.

UI components: shadcn/ui and Lucide icons.

Charts: Recharts.

Backend and database: Supabase.

Authentication: Supabase Auth.

Database: Supabase PostgreSQL.

Use environment variables for API keys and credentials.

Keep the application modular, clean, and easy to maintain.

If Supabase credentials are not configured, provide a clearly labeled demo mode with realistic sample data. Never pretend that demo data is real sensor data.

3. Website Design

Create a premium, modern sustainability dashboard with a clean green-and-white theme.

Design requirements:

Primary colors: forest green, emerald, white, and light gray.

Use a modern font, rounded cards, subtle shadows, and clean spacing.

Use responsive layouts for desktop, tablets, and mobile devices.

Add smooth transitions and interactive charts.

Use relevant sustainability icons and environmental illustrations.

Include a sidebar on desktop and a mobile-friendly navigation menu.

Make the UI look like a professional SaaS product suitable for a hackathon demonstration.

Avoid excessive animations, clutter, and oversized headings.

4. Main Pages

A. Landing Page

Create a professional landing page featuring:

Brand name: Green-Grid_SVVV.

Tagline: "Make Every Campus Resource Count."

A short explanation of the problem of resource wastage in colleges.

Key features: Resource Tracking, Waste Analytics, AI Recommendations, and Sustainability Score.

Impact statistics using clearly labeled demo data.

A sustainability dashboard preview.

Buttons: "Explore Dashboard" and "Start Tracking".

A footer with project details: KAUSHAL 8.0 Hackathon, PS-04.

B. Dashboard

Create the main dashboard with four resource cards:

Electricity Consumption — kWh.

Water Consumption — litres.

Paper Consumption — sheets.

Each card should display:

Current consumption.

Previous-period comparison.

Percentage change.

An icon and appropriate status indicator.

Add:

Weekly and monthly consumption charts.

Resource distribution chart.

Recent activity feed.

Top resource-wasting departments.

Sustainability improvement suggestions.

All charts must update based on the selected date range and available data.

C. Resource Tracking

Build a functional resource entry form with:

Resource type: Electricity, Water, Waste, or Paper.

Department or building.

Consumption quantity.

Unit displayed according to resource type.

Date and time.

Optional notes.

Requirements:

Validate inputs.

Save entries to Supabase when configured.

Update dashboard metrics and charts after successful submissions.

Allow users to view, filter, and delete records.

Show confirmation messages and meaningful error states.

D. Waste Management

Create a waste management page where users can:

Record waste generated by department.

Categorize waste as recyclable, organic, electronic, or general.

Record total quantity and disposal method.

View recyclable versus non-recyclable waste.

Track recycling rates.

View waste trends through charts.

Receive recommendations for reducing waste.

E. AI Sustainability Assistant

Build an interactive sustainability assistant that:

Analyzes recorded resource consumption.

Identifies unusually high consumption.

Suggests practical ways to save electricity, water, paper, and reduce waste.

Generates a simple sustainability action plan.

Explains why each recommendation matters.

Estimates potential resource savings using transparent calculations.

Example recommendations:

Switch off lights and fans in unused classrooms.

Fix leaking taps and monitor water-intensive areas.

Encourage digital submissions instead of unnecessary printing.

Introduce waste segregation and recycling bins.

Investigate buildings with unusually high electricity consumption.

Use a real AI API only if configured securely through a backend or Supabase Edge Function. If no AI API is configured, implement a working rule-based recommendation engine and label it accordingly. Do not fabricate AI-generated results or claim to use machine learning when it is not implemented.

F. Sustainability Leaderboard

Create a leaderboard comparing departments based on:

Resource consumption relative to department size, where data is available.

Waste segregation and recycling rate.

Verified sustainability actions.

Improvement compared with the previous period.

Allow filters by week and month. Use demo data only when explicitly labeled. Avoid rewarding departments simply for being smaller or having less recorded activity.

G. Reports

Provide:

Daily, weekly, and monthly reports.

Resource-wise consumption summaries.

Savings and sustainability score trends.

Department-level comparisons.

Export to CSV functionality.

A printable report layout.

H. Settings

Include:

User profile.

College and department information.

Notification preferences.

Demo-mode status.

Sign-out functionality.

5. Database Structure

Create suitable Supabase tables with proper relationships:

profiles: user ID, full name, role, department, college.

resource_records: resource type, quantity, unit, building, department, timestamp, notes, created by.

waste_records: category, quantity, unit, disposal method, department, timestamp.

sustainability_actions: action name, description, status, estimated savings, department, created by.

resource_targets: resource type, target quantity, period, department.

Use UUID primary keys, timestamps, appropriate constraints, and indexes where useful.

Configure Row Level Security (RLS) policies so users can only access authorized data. Do not expose Supabase service-role keys or private API keys in frontend code.

If the database is unavailable, make demo mode usable without breaking the interface.

6. Calculations and Sustainability Metrics

Implement real calculations from the recorded data:

Total consumption = sum of quantities for the selected resource and date range.

Consumption change (%) = (current period consumption - previous period consumption) / previous period consumption × 100.

Recycling rate (%) = recyclable waste / total waste × 100.

Target achievement (%) = max(0, (target - actual consumption) / target × 100), capped at 100 for display.

Estimated savings = baseline consumption - current consumption, when a valid baseline exists.

Sustainability score = a documented weighted score using normalized resource consumption, recycling performance, and completed sustainability actions.

Handle zero values, missing baselines, empty datasets, and invalid records safely. Display the assumptions used in all estimated savings and score calculations. Do not invent measured carbon savings.

7. Functional Requirements

Every important button must work.

Implement:

Search, filtering, and date selection.

Interactive charts.

Add, view, and delete resource records.

Dashboard updates after data changes.

CSV exports.

Loading states, empty states, error messages, and success notifications.

Authentication when Supabase is configured.

Demo mode with realistic sample data when credentials are unavailable.

Responsive mobile navigation.

Do not create buttons that only look functional. Avoid placeholder pages and broken routes.

8. Demo Data

Create clearly labeled sample data for a fictional college with several buildings and departments.

Include at least:

30 resource records across different resource types and dates.

15 waste records across multiple waste categories.

5 sustainability actions.

Several resource targets.

Weekly and monthly consumption trends.

Use internally consistent values so charts, totals, percentage changes, and recommendations agree with one another.

9. Hackathon Presentation Mode

Add a "Demo Mode" indicator and a quick demonstration workflow.

The dashboard should allow judges to:

View campus sustainability metrics.

Add a new electricity or water consumption record.

See the dashboard update.

View a resource-wastage warning.

Generate sustainability recommendations.

Compare departments.

Export a report.

The main demonstration should take less than three minutes.

10. Implementation Instructions

Build the actual working application, not just a design mockup.

First establish the project structure, reusable components, routes, database schema, and theme. Then implement the dashboard and resource tracking before building the remaining pages.

Prioritize reliability and a complete core workflow over adding excessive features. Test navigation, calculations, form validation, persistence, mobile responsiveness, and CSV export.

Do not leave TypeScript errors, broken imports, nonfunctional buttons, or fake integrations. If a third-party service requires credentials, explain the setup and provide a functional demo alternative.

Final Goal

Deliver a polished and working Green-Grid_SVVV MVP that demonstrates how technology can help colleges measure resource consumption, identify wastage, and take practical steps toward sustainability.

The application should be easy to understand, easy to demonstrate, technically credible, and appropriate for the KAUSHAL 8.0 PS-04 hackathon.
